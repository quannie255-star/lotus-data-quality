# clip_bench · 口径说明

> 对应代码：`clip_bench/*.py`、`modalities/image/clip_align.py`、
> `tests/test_clip_bench.py`、`tests/test_clip_integration.py`。

## 1. 指标与字段定义

| 名称 | 定义 / 公式 | 分子/分母 | 出处 |
|---|---|---|---|
| 原始余弦 cos | `⟨f_img, f_txt⟩`，两 embedding 均 L2 归一 | — | clip_align.py:`raw_cosine` |
| 对齐分 align | `clip((cos−cos_lo)/(cos_hi−cos_lo), 0, 1)`，round 6 | — | clip_align.py:`normalize` |
| cos_lo / cos_hi | 标定区间：负样本 cos 的 **p95** / 正样本 cos 的 **p50**（标定集上） | 分位数按排序索引取 | run_eval.py |
| 判定 | `cos ≥ threshold → 匹配`；threshold = 标定集约登阈值 | — | evaluate.py:`binary_metrics` |
| 约登阈值 | ROC 网格（500 点）上 `J = TPR − FPR` 最大处的阈值 | TPR=tp/(tp+fn), FPR=fp/(fp+tn) | evaluate.py:`youden_threshold` |
| AUC | Mann-Whitney 秩公式，并列分数取平均秩 | (Σ正样本秩 − n₊(n₊+1)/2)/(n₊·n₋) | evaluate.py:`auc_score` |
| auc_easy_only / auc_hard_only | 正样本分别只与易负/硬负样本合并计算 | 同上，子集 | run_eval.py |
| R@k（i2t / t2i） | 查询的正确项（对角线）排名 ≤ k 的比例；名次 = 严格大于正确项的候选数 + 1 | 分母 = 查询数 | evaluate.py:`retrieval_metrics` |
| pos / easy_neg / hard_neg | 图×真实caption / 图×随机他图caption / 图×池内最混淆非配对caption | — | dataset.py |

## 2. 什么算「对」（验收标准）

1. 指标实现与手算一致：AUC 完全可分=1.0、全并列=0.5、逆序=0.0；混淆矩阵手算用例
   （`tests/test_clip_bench.py` 前 6 项）。
2. 数据构建口径：切分不相交且同 seed 可复现；易负 caption 不属于本图；
   硬负 caption 不属于本图且是池内最混淆（替身 embedding 构造钉死）。
3. Lotus 接线：enabled=false 时 alignment=None（v0 行为，既有测试仍绿）；
   enabled=true 时第三模态键出现、权重切换；低对齐 → `remove(low_quality_modality:cross_modal)`；
   None 对齐 → `remove(no_score)`；生产配置两套权重和都=1。
4. 真实模型序关系：同一张真图，配对 caption 的 cos 必须高于错配 caption
   （`test_real_model_matched_beats_mismatched`，真实 Flickr8k 图片）。

## 3. 门禁清单（拦什么 / 坏输入会怎样）

| 门禁 | 拦什么 | 变异证据 |
|---|---|---|
| `test_mismatched_caption_removed` | 低对齐样本被放行 | 注入 align=0.05 的替身 → verdict=remove（红）；align=0.82 → pass（绿） |
| `test_none_alignment_removed_no_score` | 坏图静默放行 | 打分器返回 None → remove(no_score)，quality_score=None |
| `test_production_config_weights_sum_to_one` | 配置权重写错 | 改任一权重 → ValueError/测试红（joint_score 的键一致与和=1 双校验） |
| `test_auc_single_class_rejected` | 单一类别算 AUC | 抛 ValueError 不静默出数 |
| `test_hard_negative_mining_picks_most_confusable` | 挖掘逻辑选错样本 | 替身 embedding 错位构造 → 选错即红 |

## 4. 已知的口径坑

- **硬负样本的自证成分**：挖掘用被评模型自身 embedding——「模型认为最混淆的」
  负样本天然对该模型最难，hard AUC 因此是**偏严**口径（低估泛化到别的模型的
  难度分布）。报告必须与 easy AUC 并列呈现，不得只报其一。
- **CN-CLIP × 英文 caption = 跨语言弱口径**：预演（100/200 图）easy AUC 0.984、
  hard AUC 0.589、i2t R@1 0.58——只用于管线验证与中文侧能力对照，
  **正式英文基准数字以 OpenAI CLIP 运行为准**（tag 区分，不混表）。
- **R@k 单参考口径**：池内每图 1 条 caption；Flickr8k 文献口径是 5 条参考全算对，
  两者数值不可直接对表。
- **约登阈值在 cos 空间**，Lotus 门禁的 min_modality_score 在 **align 空间**——
  两个阈值不同空间，回填配置时换算：`align_th = (cos_th − cos_lo)/(cos_hi − cos_lo)`。
- **图像预处理口径**：HF preprocessor_config（直 resize 224×224，无 center crop）
  与官方 cn_clip 包（短边 resize + center crop）不同——同一模型两个预处理会有
  零点几个点的指标差，本仓库统一走 HF 口径并在此声明。
- transformers 5.x 兼容：get_*_features 返回 BaseModelOutputWithPooling 且
  pooler_output 已投影（不可二次投影）；image processor 须显式传 resample=BICUBIC。
  两处都在 clip_align.py 内做了版本兼容，换 4.x 也能跑。

## 5. 梯度显著图口径

demo 的热力图 = `|d(cos_sim)/d(pixel)|` 按通道求和后 min-max 归一（224×224）。
它回答「哪些像素的扰动最影响对齐分」，**不是**人类注视点、也不是 attention 权重；
命名一律用「梯度显著图」。CPU 单张约 2-5 秒（一次前向 + 一次反向）。

## 6. 口径决策（已定稿 2026-11-13，owner 采纳建议值）

- **三模态权重 {text 0.5, image 0.2, cross_modal 0.3}——定稿**。理由：文本是图文
  样本的信息主体（0.5）；跨模态对齐是本轮新增的关键判别力，给次高权重（0.3）；
  图像结构分只是字节级存在性检查、信息量最低（0.2）。这是「先上线攒账本」的起点值，
  待 hold/remove 账本积累后按真实放行/误杀分布再校准——无数据时不精调。
  权重和=1 有 `test_production_config_weights_sum_to_one` 钉住（改错即红）。
- **`clip.enabled` 定稿 = false（暂不启用）**。理由：cos_lo/cos_hi 是在 CN-CLIP ×
  英文 Flickr8k（跨语言）上标定的，而 Lotus 生产语料是中文；用错误分布的阈值给中文
  图文对判门禁 = 实验报告 §5.3 记录的「模型-语言不匹配产生比没有门禁更危险的假读数」
  （CN-CLIP 英文硬负 AUC 0.4358 < 随机）。保持 false 至中文真实图文语料就位、重标定后
  再切 true。切换是单布尔改动 + 触发多模态阶段指纹重算，代码路径已就绪且被
  `tests/test_clip_integration.py`（含真实模型序关系门禁）覆盖。
- **正式评测规模 n_calib=500 / n_test=1500——定稿为此规模**。理由：GPU 上标定 500 图
  足以稳定约登阈值、测试 1500 图（正/易负/硬负各 1500 对）的 AUC/R@k 已到三位小数稳定；
  扩到全量 8,091 图约 ×4 时间但指标不再有量级变化，性价比低。全量池留作需要更细
  误差分层（按 caption 长度/图像类别）时的升级位，不在本轮。
