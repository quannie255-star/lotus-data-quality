# clip_bench · 开发日志

> 按时间倒序，每条一个坑。格式：现象 → 定位 → 根因 → 修复 → 验证。

## [2026-11-13] 正式评测（500 标定 / 1500 测试，两模型）+ 两个新坑

### 结果
- OpenAI CLIP ViT-B/32（tag=clipb32，78.5s GPU）：约登阈值 0.2688（J=0.476）、
  AUC 整体 0.7654 / 易负 0.9930 / 硬负 0.5377、i2t R@1 0.5173。
- CN-CLIP × 英文（tag=cnclip_full，140.9s）：硬负 AUC 0.4358 **低于随机**——
  跨语言细粒度区分失效且方向反转（定量证据进口径说明与实验报告 §4.2）。

### 坑 1：Flickr8k metadata 有脏条目
现象：全量 run 在测试集阶段 `FileNotFoundError: …2258277193_586949ec62.jpg.1`。
定位：metadata.jsonl 8,092 个键 vs 磁盘 8,091 个文件——多出的 1 条是 `.jpg.1`
后缀的重复条目（数据集已知瑕疵），预演小规模恰好没抽中。
修复：`load_metadata(only_existing=True)` 剔除缺失文件条目并记入
`by_img_excluded` → 评测报告 `metadata_excluded_missing_files` 字段（剔除有账）。
验证：`test_metadata_excludes_missing_files` 钉死该行为；重跑通过。

### 坑 2：归一化区间建议公式退化
现象：两模型标定都给出 `suggest_cos_lo(neg_p95) > suggest_cos_hi(pos_p50)`——
区间反向，无法回填配置。
根因：正负分布重叠区大（负样本前 5% 比正样本中位数还高），p95/p50 组合在这种
重叠下必然退化；公式设计时默认了「分布可分」这一未声明假设。
修复：改为**约登阈值锚定**两点线性映射：align(youden_th)=0.30（对齐 Lotus
min_modality_score 门禁线）、align(pos_p95)=1.0 → cos_lo = th − (3/7)(p95−th)。
新增 `apply_calibration.py` 做可复现回填（字节级精准替换防指纹漂移，含退化校验
lo<hi 否则拒绝写入）。
验证：`--tag cnclip_full --dry-run` → cos_lo=0.3289 / cos_hi=0.523 → 正式写入
config；`tests/test_clip_integration.py` 10 passed（权重和=1 门禁仍绿）。

### 后台运行静默截断的教训
第一次 cnclip_full 后台跑「exit 0」但只输出到 calib 行——管道 `| grep | tail`
把 Python 崩溃吞了（退出码取自 tail）。重跑改 `> log 2>&1` 落盘才看到真实
traceback。教训：**后台长任务的失败证据必须落文件，不能信管道后的退出码**。

## [2026-11-12] 硬负挖掘 KeyError：metadata 路径前缀被剥掉

### 现象
`run_eval` 预演在 `add_hard_negatives` 抛 `KeyError: '3681056426_fbd6c0c92c.jpg'`。

### 定位过程
by_img 的键是 metadata.jsonl 的 file_name（**含 `train/` 前缀**）；挖掘函数里用
`Path(p).name` 从 PairSet.images 反推文件名，把前缀剥了 → 查表 miss。

### 根因
同一实体（图片）在数据结构里有两个表示（带前缀 id / 纯文件名），反推时选错了源。

### 修复
PairSet 本来就带 `image_ids`（与 by_img 键同源）——改用 `zip(pairs.image_ids, pairs.kinds)`
去重保序，不再从 Path 反推。

### 验证
预演重跑通过：calib 100/test 200 全链 62.3s，`data/clip/eval_report_cnclip_rehearsal.json`。

## [2026-11-12] transformers 5.x 双坑：resample=None 透传 + get_*_features 返回类型变更

### 现象
① `ChineseCLIPImageProcessor()(images=...)` → `TypeError: 'NoneType' object is not
subscriptable`（image_processing_backends.py:242 `pil_torch_interpolation_mapping[resample]`）；
② 修好预处理后 `feat.norm` → `AttributeError: 'BaseModelOutputWithPooling' object
has no attribute 'norm'`；③ 手动补投影又炸 `mat1 and mat2 shapes cannot be multiplied
(1x512 and 768x512)`。

### 定位过程
②③ 读 v5 源码：`get_image_features` 现在 `return vision_outputs`
（BaseModelOutputWithPooling），且内部已把 `pooler_output` **就地替换为
visual_projection 后的 512 维**——即 pooler_output 就是最终 embedding，二次投影维度必炸。
① 是 v5 legacy processor 的 bug：preprocess 的 resample 形参默认 None 被直接透传给
resize，而 mapping 查表不容 None（且 torchvision 未装时 mapping 本身是 None，
错误信息双层误导——先补装了 torchvision 0.24.1+cu126 排除该变量）。

### 根因
transformers 4.x → 5.x 破坏性变更：特征提取函数返回类型/语义变化；legacy CLIP 系
image processor 未同步适配 resample 默认值。

### 修复
clip_align.py 做**双版本兼容**：`_project_image/_project_text` 用
`hasattr(out, "pooler_output")` 分发（5.x 取 pooler_output 不再投影；4.x 直接是张量）；
image_proc 调用一律显式传 `resample=PILImageResampling.BICUBIC`（与
preprocessor_config.json 的 resample=3 同值，口径不变）。

### 验证
真实图打分序关系正确：CN-CLIP 英文 caption pos 0.4246 > neg 0.3226；
中文 caption pos 0.5039 > neg 0.2433（中文区分度显著更大，符合 CN-CLIP 主场预期）；
`tests/test_clip_integration.py` 10 passed（含真实模型门禁）。
