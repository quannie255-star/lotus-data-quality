## [2026-11-12] 基准实跑：三个反直觉发现（数字见 grad_select_bench.json）

### 现象
五档配置 × 四形态基准跑通，正确性核验全过（分数差 ≤1.5e-7、选中集合全一致），但：
① torch_loop 比纯 Python 串行**慢 2~7 倍**（×0.14~×0.49）；② GPU 臂没有跑赢 CPU
batch（同量级 ×3.4~×6.8）；③ 线程扫描平坦，**1 线程（0.1687s）快过默认 24 线程
（0.2151s）**。

### 定位过程
① loop 形态每次迭代付 torch 算子派发固定开销，Python 级循环未消除——向量单元没用上；
② 单条计算量太小（d≤128 点积），H2D 拷贝 + kernel 启动吃掉收益；③ 0.2s 量级负载
属于线程管理开销敏感区。

### 根因
三个都是「负载规模 vs 并行固定开销」的同一件事：并行收益 = 计算量 −（派发 + 传输 +
同步 + 调度）。本问题线性模型下计算量太小，只有 batch 向量化（把 N 条摊进一次矩阵乘）
稳定赚 3.6~6.8 倍。

### 修复
不是修代码——是按课程要求「优化没有带来加速时也应分析原因」，把三点写进
实验报告-P11.md §5（含 chunk 在 N=50000,d=32 反而最快 ×6.11 的缓存局部性解释）。

### 验证
`data/downstream/grad_select_bench.json`（原始记录，env 块含硬件/torch/线程数）；
报告表格数字与 JSON 逐格对应。

## [2026-11-12] 变异测试构造踩中「余弦尺度不变性」

### 现象
`test_mutation_tie_break_order` 首跑红：`assert [0, ...]`，构造的「低分样本」
`([0.5,0],-0.5)` 分数竟然是 1.0，与高分样本同分。

### 定位过程
手算：w=(1,0) 时 g=(wᵀx−y)·x=(0.5+0.5)·(0.5,0)=(0.5,0)，与 ḡref=(1,0) 的余弦=1。
梯度**方向**与参考一致，模长差异被余弦归一化吃掉。

### 根因
测试构造错误（不是产品代码错误）：余弦相似度尺度不变，改模长造不出低分样本，
必须改方向。这是打分函数本身的性质，值得进口径说明（已记为「已知口径坑」第 1 条）。

### 修复
低分样本改为正交向量 `([0,1],-1)` → g=(0,1)，cos=0。同时简化该测试：删掉
「全同分时两种排序碰巧同结果」的无效对照，改为 [1,0,1] 分数构造钉死 selected=[0,2]。

### 验证
`.venv/Scripts/python.exe -m pytest tests/test_grad_select.py -q` → 8 passed, 5 skipped
（skip 均为 torch 臂，当时 torch 还在安装）。

## [2026-11-12] 模块级 importorskip 把整个测试文件跳过

### 现象
torch 未装时 `pytest tests/test_grad_select.py -q` → `1 skipped`——**串行的 8 条用例
也全被跳过**，门禁假绿（看着没红，其实什么都没验）。

### 定位过程
pytest 输出只有 1 条 skip 记录 → 说明 skip 发生在**收集阶段**而非用例级 →
定位到 `torch = pytest.importorskip("torch")` 写在模块顶层。

### 根因
`pytest.importorskip` 在模块级调用会给**整个模块**打 skip，后续所有用例不再收集。

### 修复
改为 try/except ImportError + `requires_torch = pytest.mark.skipif(...)`，只装饰
torch 相关用例；串行用例无条件收集执行。

### 验证
修复后 `8 passed, 5 skipped`——串行用例真实执行（passed 而非 skipped），
torch 用例逐条 skip 且 reason 明确。

## [2026-11-12] 零分母变异测试预期错了异常形态

### 现象
`test_mutation_zero_denominator_convention` 首跑红：预期猴补丁产出 `nan`，
实际抛 `ZeroDivisionError`。

### 定位过程
traceback 指到 `core.py:72` 的列表推导内 `broken()` 的 `num / (ng * nr)`。

### 根因
Python float `0.0/0.0` 抛 `ZeroDivisionError`（IEEE754 nan 语义只在 numpy/torch
里默认出现）。变异断言写成了 numpy 直觉。

### 修复
断言改 `pytest.raises(ZeroDivisionError)`，并在 docstring 记录这一差异——它恰好是
「零分母约定必须显式实现」的论据：纯 Python 下不处理直接炸，torch 下不处理产出
nan/inf 静默污染排序（`_scores_from_grads` 用 `torch.where` 显式置 0）。

### 验证
`8 passed`（同上命令）。

## [2026-11-12] 课程 PDF 文本提取

### 现象
Read 工具报 PDF 有密码保护；pypdf 直读 console 输出 GBK 编码错
（`'gbk' codec can't encode character '\U0001d43a'`——数学斜体 Unicode 字符）。

再按行号读 P11 正文（p.4）与附录（p.27-30）。课程口径全部以提取原文为准。
