## 1. 指标与字段定义（lora_report.json 逐字段）

| 字段 | 定义 | 分子/分母 | 出处 |
|---|---|---|---|
| `data.n_candidates` | release 层全部非空 content 文档数，**减去**与评测行哈希重叠者 | — | data.py:`build` |
| `data.excluded_overlap` | 候选中 SHA-256 命中参考∪测试行的文档数（实测 6） | — | data.py:`build` |
| `data.k_select` | `⌈0.05 × n_candidates⌉`（2396 → 120） | — | run.py |
| `scoring.score_median` | 全候选余弦分数中位数；分数 = `gᵢᵀḡref/(‖gᵢ‖·‖ḡref‖)`，零范数记 0（与 grad_select.core 同约定） | — | model.py:`cosine_score_torch` |
| `scoring.wall_seconds` | ḡref 计算 + 全候选逐条 backward 打分总墙钟（含 tokenizer 编码） | — | run.py |
| `baseline_phi0.ppl` | 锚点 φ0（warm-up 后、正式 SFT 前）在测试集上的 `exp(token 级 NLL 微平均)` | ΣNLL/Σ有效token | model.py:`evaluate_ppl` |
| `grad_arm.ppl` / `random_arm.ppl` | 双臂各自从 φ0 SFT（120 篇 × 4 epoch）后，同一测试集同一口径 ppl | 同上 | 同上 |
| `conclusion.grad_vs_random_pct` | `(ppl_grad − ppl_random)/ppl_random × 100`；**负值 = 筛选臂更好** | 差值/随机臂 | run.py |
| `selection.overlap_grad_random` | 两种选择策略选中同一文档的数量（期望低重叠——若≈k 说明打分退化） | — | run.py |

## 2. 什么算「对」（验收标准）

1. **链路正确**：`--smoke` 全链跑通，report 各块齐全，双臂 ppl 均为有限正数。
2. **口径合规**（课程 PDF）：warm-up(1%×1ep) → 锚点固定打分（不更新参数）→
   top-5%（⌈⌉ 取整）→ SFT 4ep；参考集(64)与测试集(536)分开；两臂超参一致。
3. **防泄漏**：`tests/test_lora_data.py::test_no_leak_between_candidates_and_eval`
   ——任何候选哈希不得命中评测行（真改坏：把剔除逻辑删掉 → 该测试必须红，
   因为实测确有 6 条重叠，见开发日志）。
4. **训练任务口径**：纯文本 causal LM loss（非指令 SFT）——语料无指令对，如实声明；
   损失归一化 = HF 默认的 shift 后有效 token 平均，每条样本等权。
5. **截断口径**：打分与训练统一 `max_len=256` token（smoke=64）；超长文档尾部丢弃，
   两臂对称承受。

## 3. 已知口径坑

- **两个 ppl 引擎不可互比**：本模块 = Qwen3 token 级 ppl；既有消融 = char-5gram ppl
  （−4.3%）。数字量级差 3 个数量级属正常，各自只在自己的对照系内有意义。
- **conclusion 是单次运行**：单 seed、无 CI/显著性检验；`grad_vs_random_pct` 的
  解读边界 = 「本配置这一次谁更好」，statement 字段里固定写明，不得单独摘数字。
- **score==0 的候选**：可能是真零梯度（空文本/全 pad）也可能是恰好正交；
  `scoring.n_zero_norm` 单独计数，若异常大（>1%）需回查 tokenizer 截断。
- **锚点污染检查**：双臂必须 `_fresh_from_anchor` 重新加载——若直接复用打分后的
  model 对象，φ 仍等于 φ0（打分不更新参数），结果碰巧也对，但 warm-up 后若有人
  加了额外 step 就静默污染。报告记录 `warmup.steps` 供审计。

## 4. 门禁清单

| 门禁 | 拦什么 | 坏输入会怎样 |
|---|---|---|
| `test_no_leak_between_candidates_and_eval` | 候选/评测重叠 | 删除 data.py 剔除逻辑 → 红（实测存在 6 条重叠，非恒真断言） |
| `test_reference_test_disjoint` | 参考/测试分割被改坏 | m_ref 切片错误 → 红 |
| `test_eval_seed_guard` | 评测集种子被改 | `seed≠2026` → AssertionError（种子冻结纪律） |
| `test_deterministic_rebuild` | 数据构建引入随机性 | 任何未冻结的抽样 → 两次构建不一致 → 红 |
| smoke 运行 | 全链断（模型/显存/数据） | report 缺块或 ppl 非有限值 |

## 5. 口径决策（已定稿 2026-11-13，owner 采纳建议值）

- **训练超参定稿：维持「不调参、双臂对称」**（lr/epochs/max_len/LoRA r=8/α=16）。
  理由：本实验的因变量是「数据选择策略」，超参必须对 grad/random/full 三臂严格一致
  才成立对照；一旦按语料调参就引入第二个变量，污染归因。三配置矩阵（lr2e-4×4ep /
  lr1e-4×3ep / lr5e-5×2ep）本身就是超参敏感性分析——它证明「筛选优势只在强微调区间
  稳健」，比单点调参更有说服力。调参版（针对本项目语料找最优 lr/epoch）另立实验，
  不与选择策略对照混跑。
- **全量训练臂：已补（owner 采纳）**。在推荐生产配置 lr5e-5×2ep 下加第三臂
  `full_arm`（全部 2,396 篇候选，与 top-5% 的 120 篇同锚点 φ0、同测试集、同超参），
  回答「梯度筛选的 top-5% 是否接近全量效果」——这是数据选择价值的核心问题：若 5% 子集
  ≈ 全量，则选择省掉 95% 训练数据而不损失质量。产出 `lora_report_lr5e5ep2_3arm.json`，
  结论字段 `grad_vs_full_pct`（负值=子集不劣于全量）/`full_vs_baseline_pct`。
  三臂对照与解读见 开发日志.md 与 README「结果」表。
