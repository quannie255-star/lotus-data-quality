## [2026-11-13] 全量训练臂第三对照：更多数据胜出，5% 选择相对全量有损

### 现象
在推荐生产配置 lr5e-5×2ep 下加跑 `full_arm`（全部 2,396 篇候选，与 top-5% 的 120 篇
同锚点 φ0、同测试集、同超参），三臂 test ppl：

| 臂 | 训练文档 | test ppl | vs 基线 φ0(23.51) | vs 全量 |
|---|---|---|---|---|
| grad_arm（梯度 top-5%） | 120 | 21.671 | −7.82% | **+15.24%（逊于全量）** |
| random_arm（随机 5%） | 120 | 21.349 | −9.19% | +13.53%（逊于全量） |
| **full_arm（全量）** | 2,396 | **18.805** | **−20.01%** | — |

### 定位/根因（诚实解读，非缺陷）
1. **温和微调 + 小语料 + 全量可负担 → 数据越多越好**：full_arm（18.81）显著优于任一
   5% 子集（~21.5），全量比 5% 好约 13-15%。此配置下 5% 选择是**有损**的——省 95%
   训练数据的代价是 ppl 高 15%。
2. **梯度筛选未能在 5% 预算内逼近全量**：grad(21.67) ≈ random(21.35)，差 +1.51% 属单
   seed 噪声；两者都远逊于 full。即「用 5% 选出接近全量的子集」这个数据选择的强主张，
   在本配置**不成立**——如实报，不粉饰。
3. **与三配置矩阵一致**：梯度筛选的价值此前只在**强微调（遗忘）区间**显现（lr2e-4×4ep
   时筛选臂比随机臂少恶化 8.6%，即「选对数据减轻坏训练损伤」）；温和区间里「多少数据」
   比「怎么选」更主导。两个结论不矛盾——数据选择的收益依赖训练强度与预算约束。

### 结论口径（进 README/实验报告）
- **治理语料的下游收益成立且强**：在治理后语料全量 SFT，test ppl 降 20%（因果链终证 ✅）。
- **数据选择（top-5%）在本配置是预算-质量权衡的降级项**，不是免费午餐：省数据但损 ppl。
  选择真正划算的场景是①全量训练负担不起、或②强微调致遗忘（此时选对数据减损）——
  本实验②已证（三配置矩阵），①需更大语料/更贵模型才成立，未在 0.6B+2396 篇尺度出现。

### 验证
`data/downstream/lora_report_lr5e5ep2_3arm.json`（三臂同报告，config.full_arm=true）；
grad/random 两臂 ppl 与独立跑（lora_report_lr5e5ep2.json）逐位一致（21.671/21.349），
full_arm 复用同锚点同测试集，唯一变量=训练文档集（120 vs 2396）。全量臂 4792 步
957.9s（GPU），三臂总墙钟 1284.4s。

## [2026-11-13] 全量运行：三配置对照矩阵（正式结果）

### 运行
同一锚点 φ0、同一打分（run3 走 `--reuse-scores` 指纹校验复用，run2 重算验证了
跨运行确定性：score_median 两次独立计算均为 0.115816，选中头部完全一致，baseline
ppl 两次均 23.5105）；候选 2,396 篇（release v0.1，防泄漏剔除 6 条）、k=120、
参考 64 行、测试 536 行；打分全量墙钟耗时在不同运行间为 **799s ~ 2053s**（laptop GPU
fp32、256 token 截断；首跑 798.9s、复用锚点的重算跑 2053.4s——**墙钟随 GPU 热状态/
占用波动，非确定性量**）。真正确定性的是**分数值本身**：score_median 0.115816、
min −0.130299、max 0.477951 在多次独立运行 6 位小数一致（见下「跨运行确定性」）。

| 配置 | grad_arm ppl | random_arm ppl | grad vs random | 两臂 vs 基线 φ0(23.51) |
|---|---|---|---|---|
| lr=2e-4 × 4ep | 35.36 | 38.69 | **−8.61%（筛选臂好）** | 双双大幅变差（+50%/+65%，遗忘） |
| lr=1e-4 × 3ep | 24.10 | 23.77 | +1.41%（噪声区间） | 微差（+2.5%/+1.1%） |
| lr=5e-5 × 2ep | 21.67 | 21.35 | +1.51%（噪声区间） | **双双改善（−7.8%/−9.2%）** |

### 解读（诚实口径，进 README 路线图与实验报告）
1. **梯度筛选的优势只在强微调（过拟合/遗忘）区间稳健**：lr2e-4×4ep 时筛选臂比
   随机臂少恶化 8.6%——「选对数据能减轻坏训练的损伤」成立；
2. 温和微调区间两臂差 ±1.5%，单 seed 下属噪声——**不能声称筛选普遍优于随机**；
3. 两臂在 lr5e-5×2ep 下都改善基线（治理语料的训练收益成立），但幅度接近——
   「洗过的数据有收益」与「怎么选洗过的数据」是两个问题，本实验分别给了答案；
4. 若只跑 lr2e-4×4ep 一个配置就宣称「筛选提升 8.6%」，是**挑口径**——三配置
   矩阵正是为了防这个（quantitative-claim-audit 纪律）。

### 验证
`data/downstream/lora_report.json`（lr2e-4）、`lora_report_lr5e5ep2.json`、
`lora_report_lr1e4ep3.json`、`lora_scores.json`（打分缓存+指纹）。

## [2026-11-12] 模型下载三连坑：pytorch.org 被断 → hf-mirror 假活 → ModelScope 兜底

### 现象
① `pip install torch --index-url https://download.pytorch.org/whl/cu126` 永久无输出；
② `snapshot_download('Qwen/Qwen3-0.6B')` 走 hf-mirror.com：8/10 文件秒下，唯独
model.safetensors 卡死（15 秒零增长，incomplete blob 停在 16.7MB）；
③ 后台/前台 Python 进程均无法在工作区外建目录（`PermissionError WinError 5`，
连 bash 刚建好的目录里写文件都被拒）——HF 默认缓存 `~/.cache/huggingface` 不可用。

### 定位过程
① curl 直探 download.pytorch.org → exit 35（SSL connect error），pypi/清华/SJTU 全 200；
② hf-mirror 的 resolve URL 302 → `cas-bridge.xethub.hf.co`（xet 存储后端，被墙）——
镜像只代理了元数据没代理大文件 CDN；ModelScope 同文件直连 14.7MB/s；
③ bash mkdir 成功、Python os.makedirs 失败 → 沙箱按进程限制写工作区外路径。

### 根因
三个独立的网络/沙箱边界问题叠加：pytorch 官方源不可达；hf-mirror 大文件重定向到
被墙的 xethub；本会话 Python 进程禁写工作区外。

### 修复
- torch cu126：SJTU 镜像 curl 断点续传下载 2.58GB 轮子 → 本地 pip install（CUDA 验证通过：
  RTX 4060 Laptop 识别成功）；
- 模型：ModelScope repo API 逐文件 curl 到 `data/models/Qwen3-0.6B/`（gitignored），
  run.py 加 `_resolve_model`：CLI > 本地目录 > HF id 三级优先；
- 缓存：HF_HOME 不再依赖用户目录（本地模型直接路径加载，`HF_HUB_OFFLINE=1` 免网络探查）。

### 验证
`torch 2.9.1+cu126 cuda: True NVIDIA GeForce RTX 4060 Laptop GPU`；
模型 7 文件齐全（model.safetensors 1,503,300,328 字节）。

## [2026-11-12] 防泄漏剔除不是摆设：实测抓到 6 条真实重叠

### 现象
`data.build()` 全量运行：候选 2,396 = release 2,402 − 6，`excluded_overlap=6`。

### 定位过程
release ⊂ mix ⊂ quality ⊂ dedup ⊂ clean 的分层链路下，冻结评测集从 clean 层抽样
（seed=2026），理论上就可能抽中后来进了 release 的文档——SHA-256 对撞证实不是理论。

### 根因
既有 ppl 消融的评测集「独立冻结」靠的是**不参与训练**的纪律，但 LoRA 实验的候选集
就是 release 语料本身，纪律挡不住内容级重叠，必须做哈希剔除。

### 修复
data.py 构建候选时逐条对参考∪测试行做 SHA-256 剔除并计数进报告；
`tests/test_lora_data.py::test_no_leak_between_candidates_and_eval` 钉死。

### 验证
`.venv/Scripts/python.exe -m pytest tests/test_lora_data.py -q` → 6 passed（真实语料）。
变异方向：删掉剔除逻辑 → 该测试必红（因为重叠真实存在，断言非恒真）。
